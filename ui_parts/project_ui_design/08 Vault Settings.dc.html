Key slots

Each slot independently unwraps the same vault key. Adding or removing one does not re-encrypt anything, so it is fast and safe to change your mind.

Expensive operation
Rotate the vault master key
This is the right answer to "a copy of this file may have leaked while one of my keys was compromised". A new master key is generated, every slot is re-wrapped, and the whole body is re-encrypted. 218 connections, about 4 seconds.
Old copies of the file stay readable with the old keys. Delete them.
A vault must keep at least one usable slot. Remoter will not let you delete the last one, and deleting the recovery slot needs a typed confirmation. There is no escrow key and no support override: if every slot is lost, the file cannot be opened by anyone, including us.

Auto-lock

Locking zeroizes every key and cached secret and drops the in-memory database. Reopening needs a full unlock.

Slots are objects, not checkboxes
Each one is a row with its own identity, enrolment date, last use and revoke button — so "which keys can open this vault" has a visual answer.
The unused recovery key is amber
"Generated and never used" is exactly the slot most likely to be lost. It nags gently rather than sitting quiet until the day it matters.
Master key rotation is offered in plain words
Not hidden under "advanced" — described by the situation that calls for it, which is how the docs asked for it.
